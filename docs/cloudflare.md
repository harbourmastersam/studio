# Build and preview on Cloudflare Workers

Use Node.js 24 LTS; Wrangler requires Node 22 or later. Linux is recommended for
OpenNext builds (WSL on Windows). Install exactly the committed dependency graph:

```sh
npm ci
npm run typecheck
npm run lint
npm test -- --runInBand
npm run build
```

`npm run dev` starts Next development on port 3008. `npm run start` serves a
previous Next build. These use Node; test the Worker artifact as well:

```sh
npm run build:cloudflare
npm run preview:cloudflare
```

`npm run preview` runs both commands. The default local Worker URL is
`http://localhost:8787`. No Cloudflare credentials are required for local build
or preview. Preview is local; do not use `--remote` for this validation.

## Production configuration

The production URL is https://studio.greyharbour.net. The custom domain is
recorded in `wrangler.jsonc`; Cloudflare manages its DNS and TLS certificate.
The existing `outerbase-studio.scarlson6603.workers.dev` address also remains
enabled. The Pelican Panel origin remains `https://panel.greyharbour.net`.

In Cloudflare Workers Builds, select this repository's `develop` branch, use
`npm ci` for installation and `npm run build:cloudflare` for the build. Set Node
24 in the build environment. Configure the following **build-time** variable,
replacing the example with the actual HTTPS Pelican Panel origin:

```dotenv
NEXT_PUBLIC_EMBED_ALLOWED_ORIGIN=https://panel.example.com
```

This public value is not a secret. Rebuild whenever it changes; Next compiles it
into the client and CSP. No database/API credentials or database bindings are
required for the embed client. See [the protocol](embedding.md) for nonce URLs
and the parent responsibilities.

`wrangler.jsonc` defines the Worker name, `.open-next/worker.js` entry point,
`.open-next/assets` binding, `nodejs_compat`, observability, and compatibility
date `2026-09-25` (matching the tested Wrangler/workerd release). The existing
routes now use Next's Node runtime, as required by OpenNext. Do not restore
`runtime = "edge"` declarations.

`keep_names: false` prevents Wrangler from injecting a `__name` helper into
the script serialized by `next-themes`. This avoids a browser error on dynamic
embed pages; original function names may be less descriptive when debugging.

This app has build-time static pages plus dynamic/client routes, with no ISR or
server fetch-cache revalidation. OpenNext's read-only static-assets incremental
cache serves the build-time pages; no KV namespace, R2 bucket, account ID or
cache credentials are needed. If ISR is added later, choose a supported mutable
cache and revalidation configuration then. The old upstream KV ID was removed.

`public/_headers` gives hashed Next static assets immutable caching. Embed CSP
is generated by `next.config.js` on page responses; it is not a meta tag.

The existing `npm run deploy` script builds and deploys; it requires your
Cloudflare account authorization. It is not part of local validation. A later
user instruction authorized this task's production deployment. If separating
CI build from deploy, deploy the already
built artifact with `opennextjs-cloudflare deploy`.

## Dependency maintenance decisions

- Next, `@next/mdx`, and `eslint-config-next` are aligned on Next 15. React stays
  on the 19.0 patch line. No framework migration is involved.
- Overrides update Next's pinned PostCSS within major 8 and the existing
  TypeScript ESLint parser's pinned minimatch within major 9, addressing audit
  findings without unrelated major upgrades. Revisit them when upstream pins
  incorporate the fixes.
- SheetJS uses the official fixed 0.20.3 tarball because the npm `xlsx` release
  is stale. The lockfile records its integrity; existing export code is unchanged.
- The unused Showdown package and its types were removed. Existing markdown
  rendering does not import them.
