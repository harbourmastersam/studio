<DocContent title="Embedding Studio via iFrame" group="Integration">

Studio can render database results inside your application while your backend
retains the database credentials and executes queries. This fork requires a
configured parent origin and a fresh viewer channel. There is no built-in
Pelican broker or database session backend yet.

## Configure the parent origin

Set this public environment variable before building Studio:

```dotenv
NEXT_PUBLIC_EMBED_ALLOWED_ORIGIN=https://panel.example.com
```

Use an exact HTTP(S) origin without a trailing slash or path. Rebuild when it
changes. For local development, an exact origin such as `http://localhost:3000`
uses the same security checks. Missing configuration disables framing of embed
pages and causes iframe transport initialization to fail; normal Studio pages
remain usable.

## Embed a viewer

The parent generates a fresh cryptographically random nonce for each viewer,
for example with `crypto.randomUUID()`. It supplies that value as the single
`channel` parameter. The channel must contain 22–256 URL-safe letters, digits,
underscores or hyphens. This literal is an example only:

```html
<iframe
  src="https://studio.example.com/embed/mysql?channel=6ed3eb71-431d-4e72-9e84-8d032b6935cb"
></iframe>
```

Existing drivers such as `/embed/sqlite` use the same protocol. Optional `name`,
`color` and theme parameters remain available.

The channel binds messages to a viewer; it is **not authentication or
permission to access a database**. Never put passwords, API credentials or
authentication tokens in the URL.

## Message contract

Studio sends a query or transaction to the configured parent origin:

```json
{
  "type": "query",
  "id": 1,
  "channel": "6ed3eb71-431d-4e72-9e84-8d032b6935cb",
  "statement": "SELECT 1"
}
```

```json
{
  "type": "transaction",
  "id": 2,
  "channel": "6ed3eb71-431d-4e72-9e84-8d032b6935cb",
  "statements": ["SELECT 1", "SELECT 2"]
}
```

The parent validates the Studio origin, the iframe's `contentWindow`, the channel
and the request shape, then forwards permitted operations to its authenticated
backend. The parent must echo `type`, `id` and `channel` in every response.
A query success carries a `DatabaseResultSet` in `data`; a transaction success
carries an array of result sets. An error carries a string `error` and no `data`.

```json
{
  "type": "query",
  "id": 1,
  "channel": "6ed3eb71-431d-4e72-9e84-8d032b6935cb",
  "data": {
    "headers": [
      {
        "name": "value",
        "displayName": "value",
        "originalType": "INT",
        "type": 2
      }
    ],
    "rows": [{ "value": 1 }],
    "stat": {
      "rowsAffected": 0,
      "rowsRead": 1,
      "rowsWritten": null,
      "queryDurationMs": 1
    }
  }
}
```

```json
{
  "type": "query",
  "id": 1,
  "channel": "6ed3eb71-431d-4e72-9e84-8d032b6935cb",
  "error": "Query not permitted"
}
```

Reply using `iframe.contentWindow.postMessage(response, studioOrigin)` with the
exact Studio origin. Never use a wildcard target. Studio validates the response
origin, actual parent window, channel, pending request ID, operation and result
shape. Invalid or unexpected messages are ignored. Unmounting removes the
listener and rejects pending requests.

Embed pages use `Content-Security-Policy: frame-ancestors` with the configured
parent origin and `Referrer-Policy: no-referrer`. The parent/backend remains
responsible for authentication, authorization, credentials, query execution,
transaction handling, session lifetime and resource limits.

See the repository's `docs/embedding.md` for the full protocol and
`docs/cloudflare.md` for build and Worker preview instructions.
